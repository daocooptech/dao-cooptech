# ДАО КООПТЕХ — функциональная спецификация MVP

Статус: черновик v1, на основе существующего HTML/CSS-прототипа (`/`).
Назначение документа: детализировать 8 основных разделов платформы по единым пунктам, зафиксировать, что уже сделано в макете, что нужно доделать для MVP, и какие вопросы передать агентам `coop-economist` и `decentralized-dev`.

---

## 0. Общие принципы и сквозные паттерны

### 0.1 Структура интерфейса (уже реализовано)
- **Топбар**: логотип, название платформы, поиск по всей платформе, «настройки», «выйти». Фон — чёрный (`--ink`), полоса-акцент снизу — тёмно-зелёная (`--teal`); так же и на публичном лендинге (`.public-header` на `index.html`). Пробовали зелёную шапку — вернули чёрную по решению владельца продукта; заголовки каруселей (`.cat-header`) при этом остаются зелёными как отдельный, уже согласованный акцент.
- **Сайдбар**: 8 основных разделов + блок «Расширения» (10 модулей: аналитика, цифровые активы, образование, целевые программы, аукционы, библиотеки, бартер, диск, здоровье, мероприятия — аналитика первым пунктом, мероприятия последним; ЖКХ убрано из состава). Расширения в MVP — вне скоупа, кроме как ссылки-заглушки.
- **Паттерн «Каталог → Карточка → Детальная страница»**, общий для Людей, Навыков, Вакансий, Ресурсов, Проектов, Организаций:
  1. Каталог: карточки + панель фильтров справа + поиск сверху.
  2. Карточка: превью-иллюстрация/фото, бейдж-число (%, шт. и т.п.), геометка, название.
  3. Детальная страница: вкладки (`entity-tabs`), шапка (иконка/фото + название + бейдж-тип + стек кнопок действий), контент (описание, статистика, связанные сущности).
- **Переключатель «списком / плиткой»** (`.view-toggle`, две кнопки ☰/▦) — теперь на всех 6 каталогах. У Людей/Навыков/Вакансий (`.vacancy-list`) список — вид по умолчанию, плитка через класс `.tile-mode`. У Ресурсов/Проектов/Организаций (`.ptile-grid`) плитка — вид по умолчанию, список через класс `.list-mode` (JS при первом переключении генерирует текстовую строку `.list-meta` из данных бейджа/геометки). На «Проектах» один переключатель разом управляет всеми тремя подборками (Новые/Самые посещаемые/Космос). Плиточная сетка — фиксированно 5 карточек в ряд.
- **Локальные фото вместо внешнего фото-сервиса**: `loremflickr.com` (71 изображение на `my-page.html`, `person.html`, `messages.html`, `projects.html`, `resources.html`) 2026-08-09 стал отдавать HTTP 500 — сервис недоступен, его типовая замена Unsplash Source тоже отключена (503), без платного API нет надёжного источника тематических фото по ключевым словам напрямую. Первая итерация — 31 SVG-значок по темам — владелец отклонил («не красиво, скачай всё-таки картинки»). Финально: **42 реальные фотографии скачаны с Wikimedia Commons** (свободная лицензия, есть публичный API без ключа) и сохранены локально в `images/photos/*.jpg` — по темам (автокран, цемент, брус, арматура, бетономешалка, деньги, экскаватор, доски, сварка, кирпич, ремесленная мастерская, бетоновоз, леса, утеплитель, генератор, кровля, склад, 3д-печать, теплица, сортировка мусора, мастерская/FabLab, прачечная, коворкинг, ремонт фасада, модульный дом, солнечная станция, мост, переработка, площадка, пекарня, ветропарк, реставрация, уличная библиотека, пластик на переработку, пешеходный мост, технопарк, электрик, веб-дизайн, морковь, микроавтобус, программист, деловая встреча). Полностью локально, без сетевых зависимостей при показе сайта. Подбор шёл с ручной проверкой релевантности по названию файла перед скачиванием (не «первый попавшийся результат поиска» — часть неточных совпадений пересмотрена и переискана). `i.pravatar.cc` (фото людей) не трогали — работал исправно. На случай будущего сбоя ЛЮБОГО внешнего изображения (в т.ч. pravatar) на этих 5 страницах остаётся общий `<script>` в `<head>` — при ошибке загрузки `<img>` подменяется на встроенную SVG-заглушку.
- **Единая «шапка рабочей области» каталога**: строка `.search-row` (поиск + основная кнопка-действие «Добавить…»/«Разместить…»/«Создать резюме» + `.view-toggle` справа через `margin-left:auto`) — теперь одинаковая структура на всех 6 каталогах (Проекты, Организации, Ресурсы, Вакансии, Навыки, Люди), по образцу страницы «Проекты». `.cat-section-title` под ней теперь содержит только заголовок подборки и счётчик найденного, без переключателя вида. **Над `.search-row`** — тоже единообразно `.entity-tabs` (не `.page-title`) на всех 6 каталогах: одна активная вкладка с названием каталога (напр. «Каталог организаций», «Все навыки», «Все вакансии») — тот же 13px/подчёркивание teal, что и на детальных страницах и на «Проектах» (там вкладок три: Каталог/Лента новостей/Идеи — уникально для Проектов, у остальных каталогов пока по одной вкладке). Раньше на этих 5 страницах был крупный чёрный `.page-title`-заголовок — визуально не совпадал с «Проектами», это было замечено и исправлено.

### 0.2 Состояния, которых пока нет в прототипе (нужно добавить для всех разделов)
- Пустое состояние («у вас пока нет ресурсов/проектов/контактов» + призыв к действию).
- Состояние загрузки.
- Состояние ошибки / нет доступа.
- Подтверждение действия (например, «вы уверены, что хотите откликнуться на вакансию?»).
- Мобильная адаптация — сейчас всё desktop-first.

### 0.3 Сквозные открытые вопросы → на консультацию агентам
- **`coop-economist`**: как считается «уровень доверия» (%), что такое «баланс» и в каких единицах (реальные деньги / внутренняя валюта кооператива / условные баллы), как считаются «доли/паи» в проекте, что происходит при споре/невыполнении обязательств.
- **`decentralized-dev`**: схема сущностей и связей (Человек–Организация–Проект–Ресурс–Навык–Вакансия), модель идентичности и аутентификации, что и как синхронизируется между узлами при будущей децентрализации, нужен ли единый или федеративный реестр пользователей на старте.

## 1. Моя страница (`my-page.html`)

**Назначение**: личный кабинет пользователя — визитка + всё, чем человек владеет/умеет/участвует, в одном месте. `index.html` теперь отдельная публичная лендинг-страница проекта (для неавторизованных посетителей), «Моя страница» — это персона в собственном, редактируемом режиме (структурно тот же шаблон, что и просмотр чужого профиля в `person.html`).

**Статус в прототипе**: наиболее проработанный раздел, уже доведён до интерактивного демо (см. ниже).

**Уже есть**:
- Обложка профиля — фото (не абстрактная заглушка), с кнопкой «Изменить фото» (реальная загрузка + предпросмотр через FileReader, без бэкенда).
- Статы текстом: доверие %, баланс, контракты, подписчики.
- **Уровень доверия — решено**: двусторонние отзывы после каждой сделки, записываются в блокчейн (неизменяемы задним числом). Пример: 33 положительных отзыва из 35 оценённых сделок → 92%. Отражено в подсказке «как считается?» рядом со статой.
- Инфо-блоки: контакты (город, телефон, мессенджеры, соцсети — со сгруппированными подзаголовками), личная информация (день рождения, языки). Текстовый блок-дублёр «Связи» и блок «Приватность» убраны по решению владельца продукта.
- Карусели категорий, все шириной в ленту (620px), свёрнуты по умолчанию (разворачиваются по клику на заголовок), с рабочей горизонтальной прокруткой и плиткой «+ Добавить»: **Связи** (бывш. «Люди» — друзья/коллеги/родственники, переименовано во избежание путаницы с разделом «Люди»), Образование, Навыки, Ресурсы, Проекты, Достижения, Потребности (со статусом открыта/закрыта), Организации (роль человека в организации — учредитель/совладелец/подрядчик; сознательно не называем «Предприятия», чтобы не плодить дубль термина с разделом «Организации»).
- Иконки карусели: Связи/Образование/Достижения — единый набор line-icon SVG (teal, уменьшены на 15% и отцентрованы в плитке); Навыки/Ресурсы/Проекты/Потребности/Организации — реалистичные фото-заглушки (loremflickr).
- Ф.И.О. владельца (`.profile-name`, поверх `.page-title`) — цвет и шрифт приведены к виду заголовков карусели (`.cat-header`, как у слова «Связи»): `var(--teal-dark)` вместо чёрного, `Inter` вместо `Space Grotesk`; размер (26px) не менялся. Тот же класс — на `person.html` (чужой профиль).
- Личная лента/стена: счётчик записей, композер «Что у вас нового?» с рабочей публикацией (JS), посты с аватаром, вовлечённостью и превью медиа.
- **Показ профиля другим участникам** — модальное окно («⚙ Что видят другие по умолчанию» под именем): владелец отмечает чекбоксами, какие из 8 карусельных блоков будут раскрыты сразу — при каждой загрузке страницы, без клика по заголовку. Один и тот же выбор применяется и на `my-page.html` (собственный вид владельца), и на `person.html` (что видят другие участники) — при следующей загрузке страница снова показывает выбранные блоки, свернуть/развернуть вручную в моменте по-прежнему можно. Хранится в `localStorage` (демо без бэкенда). **Заводской дефолт** (пока владелец ни разу не сохранял свой выбор) — раскрыты Навыки, Ресурсы, Проекты, Потребности; Связи/Образование/Достижения/Организации свёрнуты.

**Нужно доделать для MVP**:
- Форма/режим редактирования полей профиля — сейчас точечные поля (контакты, личная информация) переключаются в contenteditable по кнопке-карандашу, полноценной формы сохранения ещё нет.
- Управление приватностью полей (кому видны контакты/личная информация и т.п.) — пока не в макете (блок убран по просьбе владельца продукта); появился первый шаг в эту сторону — настройка «раскрыт по умолчанию» для блоков карусели (см. выше), но видимость самих данных пока не регулируется.
- Раздел «Потребности» — нужно решить, это просто список тегов или отдельная мини-сущность со статусом и откликами (статус открыта/закрыта в макете уже есть).
- Распространить тот же фото-подход (обложка, карусели) на `person.html` и каталоги — сейчас фото есть только в `my-page.html`, `person.html` (только обложка) и каталоге `people.html`.

**Данные профиля (черновой список полей)**:
ФИО, фото обложки, город, телефон, мессенджеры (Whatsapp/Viber/Telegram/Skype), сайт, привязанные приложения (GitHub и т.п.), день рождения, языки, уровень доверия (% = положительные/все отзывы за сделки), баланс, число контрактов, число подписчиков, списки образования/навыков/ресурсов/проектов/достижений/потребностей/организаций.

**Связи с другими разделами**: Люди (карусель «Люди» = связи), Навыки (мои навыки ↔ каталог навыков), Ресурсы (мои ресурсы ↔ каталог), Проекты (мои проекты), Организации (я состою в…), Сообщения («написать»), Лента (личная лента ↔ общая `feed.html`).

**→ economist**: правило подсчёта доверия решено (см. выше) — уточнить у `coop-economist`, как именно фиксируется «двусторонний» отзыв (обе стороны должны оставить оценку, иначе сделка не засчитывается в знаменатель?) и что происходит при споре/отказе одной стороны оставить отзыв.
**→ decentralized-dev**: отзывы «на блокчейне» — нужно решить, какой именно смарт-контракт/реестр фиксирует пару (сделка → два отзыва), и как это соотносится с «пока не решено» по стеку MVP в целом.

## 2. Сообщения (`messages.html`)

**Назначение**: личные и групповые переписки между людьми/организациями, привязанные к сделкам/проектам.

**Статус в прототипе**: полноценное интерактивное демо — переключение тредов, поиск, вложения, эмодзи, отложенная отправка (JS, без бэкенда). Список диалогов — 230px, сама чат-панель — 620px (равна ширине контентной колонки «Моей страницы»), итого блок сообщений 850px. Верх рабочей области приведён к общему виду каталогов — `.entity-tabs` с одной активной вкладкой «Сообщения» вместо `.page-title`.

**Уже есть**:
- 4 типа тредов: личная переписка (Иванова Мария — фото-аватар), переписка от лица организации (ООО «Мириталь», Кооператив «Шукты» — квадратный инициал-аватар в бренд-цвете), **закрытый** групповой чат проекта (Строительный 3д принтер, 🔒, ссылка «Открыть проект →» на `project.html`), **публичный** групповой чат (ДАО КООПТЕХ — общее собрание, 🌐, ссылка на `organization.html`). Групповые реплики подписаны автором.
- Поиск по названию треда (живой JS-фильтр списка).
- Клик по треду переключает переписку без перезагрузки; непрочитанные помечены точкой и сбрасываются при открытии.
- Композер с панелью вложений (📎): фото и документ — реальный выбор файла с превью-чипом перед отправкой; геопозиция и контакт — демо-карточки; **расширение** — подменю из каталога 9 расширений, вложение уходит в чат кликабельной карточкой-ссылкой на страницу расширения.
- Эмодзи-панель (😊, 24 знака, вставка в текст). Стикеры временно убраны из тулбара по решению владельца продукта — возможно, вернутся отдельным заходом позже.
- Отложенная отправка (🕒): выбор даты/времени, сообщение уходит в панель «Запланировано» под композером с действиями «отправить сейчас» / «отменить» (без реального таймера — демонстрация механики).
- Отправка текста (Enter/кнопка) добавляет пузырь и обновляет превью последнего сообщения в списке.

**Нужно доделать для MVP**:
- Статусы онлайн/оффлайн, «печатает…».
- Реальные фоновые таймеры для отложенной отправки (сейчас только ручной перевод «отправить сейчас»).
- Архивирование, блокировка пользователя.
- Уведомление о новом сообщении в топбаре/через `notifications.html`.
- Пустое состояние («нет сообщений», «ничего не найдено» — сейчас при пустом поиске список просто пропадает без пояснения).

**→ economist / decentralized-dev**: публичные групповые чаты (как у «ДАО КООПТЕХ») поднимают вопрос модерации и голосования сообщений — вероятно, требует отдельной механики позже.

**Связи с другими разделами**: Люди/Организации (кнопка «Написать» на детальной странице), Проекты (групповой чат участников), Уведомления.

## 3. Люди (`people.html` + `person.html`)

**Назначение**: каталог всех участников платформы — поиск специалистов, партнёров, соседей по кооперативу.

**Статус в прототипе**: каталог готов (сетка с реальными фото + фильтр), детальная страница `person.html` — самостоятельный режим просмотра, отделённый от «Моей страницы».

**Уже есть**:
- Каталог: карточка (фото, город, ФИО — без % доверия на самой карточке, показатель убран с фото по решению владельца продукта). **33 участника** (было 23 — добавлено 10, чтобы новые категории специализации не пустовали).
- **Специализация — то же дерево hh.ru, что у Навыков/Вакансий** (общий `CATEGORY_TREE`, 27 профобластей × подкатегории; каждому человеку присвоена категория/подкатегория по основному навыку) — каскадный фильтр Специализация → Подкатегория.
- **Фильтр — рабочий** (JS, живая фильтрация всех карточек): Специализация/Подкатегория, город — комбобокс с автодополнением (datalist), навыки — множественный выбор с чипами (ввод + подсказки, можно выбрать несколько, снимаются крестиком), уровень доверия — выпадающий список порогов (Любой/90%+/75%+/50%+). У каждого поля — всплывающая подсказка (ⓘ, title). Есть кнопка «Сбросить» и пустое состояние («никого не нашлось» + сброс).
- Детальная страница `person.html`: та же визуальная система, что на «Моей странице» (фото-обложка, карусели с фото/line-icon, ширина 620px, сворачивание по умолчанию), но в чистом режиме просмотра — **без** карандашей редактирования, плиток «+ Добавить» и композера ленты (только просмотр чужих записей, без возможности постить от чужого имени). Вместо этого — блок действий «Написать» (→ `messages.html`) / «Подписаться» рядом с именем.
- Заголовки каруселей (`.cat-header`, общий компонент с «Моей страницей») — фирменный зелёный (`--teal`) вместо чёрного, полностью скруглённые углы в свёрнутом состоянии, скругление только сверху при развороте (стыкуется с блоком плиток).

**Нужно доделать для MVP**:
- Сортировка (по доверию, по активности, по близости).

- Бартер: как ищется совпадение (я предлагаю цемент, ищу экскаватор — как система сводит две стороны)? Сейчас это просто список тегов-пожеланий, без механики match-making.
- Мультивладение: если ресурс доступен у нескольких — как выбрать конкретного поставщика при заказе.

**Данные ресурса**: название, тип (материальный/оборудование/финансовый), описание, единица измерения, владельцы (люди/организации), способы получения (Продажа/Аренда/Рассрочка/Лизинг/Безвозмездно/Обмен/Участие в проекте) с ценой/условиями по каждому, валюта (₽/$/€/₿/USDT/ЦФА платформы), бартер-предпочтения (список), участие в проектах (проект + доля), город, фото.

**Связи**: Люди/Организации (владельцы), Проекты (ресурс, нужный для проекта, с долей/паем — см. раздел 7; теперь также обратная связь — с самого ресурса видно, в каких проектах он уже участвует).

**→ economist**: (1) правила ценообразования и распределения при коллективном владении ресурсом; (2) как курс между ₽/крипто/ЦФА платформы формируется и кто его устанавливает — рыночно или фиксированным протоколом; (3) механика бартер-мэтчинга (как система сводит две стороны с взаимно интересными предложениями); (4) как «доля в проекте от внесённого ресурса» соотносится с «долей от вложенного труда» (тот же нерешённый вопрос, что и в разделе 7); (5) новое — владелец продукта явно хочет видеть на карточке ресурса статистику «сколько сделок за ₽ / за токены платформы / по бартеру» — нужна методология, что считается «сделкой» для этой статистики и как она агрегируется (по ресурсу? по позиции склада? по производственной партии?).
**→ decentralized-dev**: (1) если сделки в крипте/ЦФА должны быть верифицируемы он-чейн (как отзывы о доверии) — стоит ли уже сейчас закладывать модель хранения истории сделок по ресурсу; (2) новое и крупное — владелец продукта прямо обозначил цель интеграции с ERP-системами производителей/владельцев ресурсов, чтобы остаток на складе и статус производственных/подготовительных этапов подгружались в реальном времени для КАЖДОГО ресурса в каталоге. Это архитектурно значимое решение (внешние интеграции, синхронизация данных, right-time updates на карточке товара) — сейчас в прототипе это только статичный демо-блок с пометкой «концепт», нужна архитектурная проработка: какой протокол/формат обмена с ERP ожидается (REST-вебхуки? файлы? прямой доступ к БД?), как часто обновляются данные, что происходит при рассинхронизации.

## 7. Проекты (`projects.html` + `project.html` + `feed.html`)

**Назначение**: совместные инициативы (от постройки 3D-принтера до теплицы) — центральный механизм превращения ресурсов и труда людей в общий результат.

**Статус в прототипе**: самый развёрнутый раздел после «Моей страницы».

**Уже есть**:
- Каталог с секциями («Новые проекты», «Самые посещаемые», категория «Космос» — вероятно тематические подборки), вкладки над каталогом: Каталог / Лента новостей / Идеи. Секция «Новые проекты» — основной список, **20 проектов** (было 3), карточки переведены с абстрактных SVG на **реальные фото** (Wikimedia Commons), как остальные каталоги платформы; «Самые посещаемые» и «Космос» пока остаются меньшими подборками-заглушками (по 3, не пересчитаны).
- **Категории — дерево по образцу Planeta.ru** (крупнейшая российская краудфандинговая платформа, категории подсмотрены напрямую в её фильтре): 🏛️ Архитектура и Урбанистика, 🌱 Экология и природа, 🤝 Общественные инициативы, 💡 Технологии и инновации — 4 из ~23 реальных категорий Planeta.ru, отобраны как релевантные кооперативным стройка/эко/сообщество-проектам; у каждой свои подкатегории (собственные, не с Planeta.ru — там подкатегорий нет). Каскадный фильтр Категория → Подкатегория.
- Карточка: иллюстрация, % готовности, город, название. **Фильтр качественный**, единый (вместо прежних двух отдельных панелей): Категория/Подкатегория, Город — комбобокс, Готовность — пороги (Любая/90%+/75%+/50%+), живая JS-фильтрация работает сразу по всем трём секциям каталога, пустое состояние.
- Детальная страница: вкладки (Каталог, О проекте, Лента, Участники, Предложения, Чат), шапка с действиями («Принять участие», «Подписаться на новости»), кольцевой индикатор готовности, описание, блок «Для чего это», таблица «Необходимые материальные ресурсы» (номер, ресурс, кол-во, стоимость, **доля/пай**, кнопка «Участвовать» на каждой строке).

**Нужно доделать для MVP**:
- Вкладка «Идеи» (в шапке каталога) — отдельный поток предложений новых проектов до их «одобрения»? Нужно решить статус-модель: идея → проект → активный → завершён/заморожен.
- Вкладка «Предложения» на детальной странице проекта — предложения по ходу проекта (аналог issue-трекера)?
- Логика кнопки «Участвовать» в строке ресурса — что происходит: бронирование доли, заявка на согласование, автоматическое зачисление доли?
- Раздел «Космос» в каталоге — тематические категории проектов нужно сделать управляемым списком, а не хардкодом.
- Форма «Добавить проект»: название, описание, «для чего это», организация-инициатор (опционально), список нужных ресурсов с долями, целевые сроки/этапы.
- Этапы/дорожная карта проекта — в `styles.css` уже есть готовые, но не подключенные компоненты `.sched-tabs`/`.task-phase`/`.task-sub`/`.output-row` (роадмап с фазами и результатами) — вероятно предназначались для вкладки «О проекте», стоит их использовать.
- Статус готовности (%) — кто и как его выставляет.

**Данные проекта**: название, описание, «для чего это», % готовности, город, организация-инициатор, список необходимых ресурсов (кол-во, стоимость, доля/пай, кто участвует), участники, этапы/роадмап, лента новостей.

**Связи**: Ресурсы (нужные ресурсы), Люди/Организации (участники, инициатор), Вакансии (проект может публиковать вакансию), Сообщения (чат проекта).

**→ economist**: ключевой вопрос всего MVP — как именно считается «доля/пай» участника (по вложенному ресурсу? по труду? фиксированная сетка?), что она даёт (право голоса, право на результат, оба), что происходит с долей при выходе участника.

## 8. Организации (`organizations.html` + `organization.html`)

**Назначение**: юридические и неформальные объединения на платформе — коммерческие компании, НКО, кооперативы, ДАО — как акторы наравне с людьми.

**Статус в прототипе**: каталог и детальная страница проработаны, структура близка к «Ресурсам».

**Уже есть**:
- Каталог: карточка (**логотип-инициалы вместо иконки** — `.org-logo`, тот же принцип, что у `.logo-square` на карточках вакансий: 2 буквы названия, чередование фирменных teal/gold-плашек; % доверия убран с самой плитки — остаётся только в фильтре и на детальной странице; город, название). **28 организаций** (было 4, затем 20, добавлено ещё 8, чтобы отраслевые категории не пустовали) — все 4 юридических типа представлены (Коммерческая, Некоммерческая, Кооперативная, ДАО), разные города. **Отрасль — то же дерево hh.ru, что у Людей/Вакансий/Навыков** (общий `CATEGORY_TREE`) — каждой организации присвоена отрасль/подкатегория по роду деятельности; каскадный фильтр Отрасль → Подкатегория, независимый от «Типа» (юридическая форма — отдельная ось). **Фильтр качественный**: Отрасль/Подкатегория, Тип — список, Город — комбобокс, Уровень доверия — пороги, живая JS-фильтрация, пустое состояние.
- Детальная страница: вкладки (Каталог, Об организации, Лента, Участники), шапка (иконка + название + бейдж типа + действия «Написать»/«Подписаться»), статы (кольцо доверия, баланс, город), контакты. **Содержание страницы дополнено по образцу старого макета freepe.io** (`organization.html`/`resource.html` из архива `freepe.github.io-master`, показанного владельцем) — под низ страницы добавлены 7 сворачиваемых блоков-каруселей (переиспользован существующий компонент `.cat-row`/`.cat-header`/`.cat-track`/`.cat-tile` с person.html, с горизонтальной прокруткой стрелками): **Участники** (реальные люди с аватарами и ролью — учредитель/бухгалтер/менеджер проектов), **Продукция и услуги**, **Способы оплаты** (эмодзи-иконки: наличные/банковский перевод/токены платформы ◆ЦФА/криптовалюта), **Ресурсы** (те же позиции, что уже принадлежат этой организации в каталоге ресурсов — кросс-связь с разделом 6), **Проекты**, **Потребности** (открытые вакансии/нужные ресурсы/финансирование — со статусом «открыта»/«закрыта»), **Партнёрские организации** (плитки-инициалы `.org-logo`, тот же алгоритм, что в каталоге). Все карусели свёрнуты по умолчанию, разворачиваются по клику на заголовок.

**Нужно доделать для MVP**:
- Ролевая модель участников организации: кто может публиковать проекты/вакансии/ресурсы от её имени, кто видит финансы, как происходит вступление в кооператив/ДАО (заявка + голосование? просто приглашение?).
- Явно развести типы (Коммерческая / Некоммерческая / Кооперативная / ДАО) по правам и механикам — вероятно, только кооперативы и ДАО получают долевые/голосовательные механики проектов из раздела 7.
- Форма «Добавить организацию»: название, тип, город, контакты, устав/правила (для кооперативов/ДАО).
- История/лента организации (вкладка «Лента») — что публикуется: новости, изменения в составе, решения собраний?
- Блоки-карусели сейчас, как и на person.html, заполнены статическим демо-контентом для одной организации (ООО «Мириталь») — при реальных данных каждая организация должна собирать свои 7 блоков из своих же связанных сущностей.

**Данные организации**: название, тип, город, адрес, телефон, сайт, % доверия, баланс, проекты, группы/роли участников.

**Связи**: Люди (участники, роли), Проекты (инициированные), Ресурсы (принадлежащие организации), Вакансии (публикуемые), Сообщения.

**→ economist**: правила голосования и распределения решений для кооперативов/ДАО — вероятно, главное отличие типа организации «ДАО КООПТЕХ» от ООО должно проявляться именно здесь.
**→ decentralized-dev**: если ДАО-организации в перспективе управляются он-чейн/через децентрализованное голосование — на это стоит закладывать модель данных уже сейчас (даже если голосование в MVP — просто таблица в обычной БД).

## 10. Рекомендуемый порядок работы над MVP

Все 8 основных разделов и Вакансии теперь есть в макете хотя бы в виде интерактивного демо. Дальше:

1. **Экономический слой** (доверие — решено, доля/пай, баланс, вознаграждение по вакансиям — типы уже заложены в фильтр) — требует решения `coop-economist` и пронизывает все разделы; лучше зафиксировать правила до того, как формы «Добавить …» будут реализованы в бэкенде.
2. Формы создания/редактирования сущностей (сейчас везде есть кнопки «Добавить …»/«Разместить вакансию», но ни одной работающей формы) и параметризация детальных страниц (сейчас `person.html`/`resource.html`/`skill.html`/`vacancy.html`/`project.html`/`organization.html` всегда показывают один и тот же демо-экземпляр независимо от того, с какой карточки перешли — нужен бэкенд с реальными ID).
3. Ролевая модель организаций — режим просмотра «своя страница vs чужая» уже решён для Людей (`my-page.html` vs `person.html`), для организаций пока нет.
4. Состояния (пустые — уже есть у Людей/Ресурсов/Проектов/Организаций/Навыков/Вакансий; загрузка/ошибка — нет) и мобильная адаптация — доводка после того, как контент всех разделов зафиксирован.

## 11. Как пользоваться агентами-помощниками

В проекте настроены три именованных саб-агента (`.claude/agents/`), их можно звать явно в любой сессии:
- **`ux-ui-designer`** — детализация экранов, новые состояния, правки HTML/CSS в едином стиле.
- **`coop-economist`** — модели доверия/доли/вознаграждения/распределения, кооперативные механики.
- **`decentralized-dev`** — схема данных, архитектура бэкенда, путь к децентрализации.

Пример вызова: «пусть `ux-ui-designer` спроектирует раздел Вакансии по этой спецификации» или «спроси `coop-economist`, как считать долю участника в проекте».
